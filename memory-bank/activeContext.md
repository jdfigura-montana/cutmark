## Decisions made while coding

- Recorder Phase 13 R4-fix (2026-11-23): `ui_kit::segmented_filled(ui, id_salt, &mut index, labels, tooltips)` joins `segmented` (both now share one `segmented_impl`; `segmented`'s behavior is unchanged) for controls that must fill their row: equal cells over the available width minus the 3px track padding, one tooltip per segment. The Layout View row uses it with the short labels "Screen"/"PiP"/"Cam" and the full names as tooltips (`layout_ui::view_choice`, `VIEWS`/`VIEW_NAMES`), because the full labels cannot fit three equal cells in the 340px panel. The right panel's tool strip now ends in a hairline running edge to edge of the panel (`ui.max_rect().x_range().expand(PANEL_PADDING)` at `strip.rect.bottom()`, the `panel_header` pattern; a Frame child inherits the panel painter's clip, so it is not clipped to the frame's inner rect). The settings ScrollArea keeps `auto_shrink(false)` and its inner ui does `set_max_width(ui.available_width())`. preview_ui now reserves the toolbar's leftover space minus `DECK_SPACE` (88px, the deck R7 adds) and paints the dark backdrop as a centered 16:9 box; the picture letterboxes inside it as before (MAX_HEIGHT_SHARE/AREA_ASPECT/MIN_AREA_HEIGHT deleted). Gotchas: `Id::with` hashes the type of its argument, so `Id::new("x")` and `"x"` are different ids; a unit test querying a widget by id must build the same chain (`Id::new("filled-cells")`, not `"filled-cells"`), and any test laying out text needs `crate::apply(&ctx)` first (fonts). `tool_strip` returns a plain `Response` (no `.response`).

- Recorder Phase 13 R4 (2026-11-23): the tool panels are now all inspector groups with no group titles (matching R3b's Camera/Key panels; the rows' own labels identify each group). `rate_control_editor` was rewritten from a two-column grid to inspector rows and draws its field errors as red `error_line`s under the row they belong to (the old grid `row()` helper is gone); the Quality slider stays a stock egui Slider because `quality` is u8 and `ui_kit::slider` is f32-only. `profile_ui::ProfileSection` lost `show`/`picker_row`/`fields` and gained `output_panel` (Profile actions group + Encode group + Format group), a pub `picker` (the dropdown alone, also used by the preview toolbar), a parked `naming_fields` (Project + Naming template only, no next-take line), `next_take(store, settings) -> (Option<String> label, String path)` with a 2 s cache, and `take_label` (trailing "takeNN" of the take name, whole name as fallback; unit-tested). `segmented` requires a `&'static str` id_salt, so `layout_ui::choice` takes one too. The preview panel toolbar is built with `allocate_ui_with_layout` at `size::PANEL_TOOLBAR_HEIGHT` + a hairline bottom line copied from the panel-header pattern; the right side is a `right_to_left(Align::Center)` with_layout holding one caption label "Next take takeNN" whose tooltip is the full path. Chips are `ui_kit::chip` (allocate-based, they respect add_enabled_ui); the Matte view chip is disabled while the profile's key is off (`webcam.settings(...).is_some_and(|s| s.key.enabled)`). Profile switching from the toolbar and the Output group both report through `ProfileOutcome`, applied by the new `app::on_profile_outcome` helper (push settings + save). The parked column now holds only: banners, Hide-from-capture, Marks, recording/summary panels, Naming fields, Countdown, Pre-flight, Control API, Tracks, Hotkeys, Recent commands; it is only reachable via the Audio tool. The camera ISO group dropped its Camera offset row (that lives in the Camera tool's Sync group) and no longer writes `offset_ms` on edit.

- Phase 7b: the is_custom() gate for the caption buttons lives in main_toolbar, not in the caption_buttons widget, so kittest tests can drive the widget directly (is_custom() is always false in a harness). egui 0.36 ViewportCommand::Minimized takes a bool. Unfocused text dimming uses `override_text_color` on the toolbar's child Uis: egui Labels follow it, widgets that paint their own galleys (primary button, icon buttons) ignore it, which is exactly the spec split. New color tokens live in a new `color.chrome` subgroup of tokens.json; the generator flattens subgroups into CAPTION_* consts. Caption region carving: subtract holes from the bar with strips clamped to each piece (unclamped strips double-counted area, caught by the unit test); kittest overlap checks must use `intersect(..).is_positive()` because emath `intersects` counts edge-touching as intersecting.
- kittest 0.36 observation pattern for viewport commands: after `Node::click()`, step and read `harness.output().viewport_output.get(&ViewportId::ROOT).commands` (same pattern video-ui uses).
- Phase 8a egui 0.36 findings: menu items and the menu bar size from `spacing.interact_size.y` (Button min height), so 32px menu rows = set that; `animate_value_with_time` holds the old value on the target-change frame and animates from the next frame; egui has NO main-align for non-wrapping rows and `main_align` is ignored even with wrap, while `top_down(Align::Max)` + `horizontal()` renders the row RTL (code-first rightmost) — so dialog footers are right-aligned by placing the LTR row in a child ui against the right edge using its width measured the previous frame (cached temp under id.with("footer")); Area response ids get a `.with("move")` suffix (never id-match an Area response); `ctx.fonts_mut` (not `fonts`) for layout_job; temp ctx data survives across frames (purged only at shutdown).
- Transport deck drag: the drag surface is a full-deck child ui with Sense::click_and_drag registered BEFORE the buttons, so buttons (later = on top) keep clicks while any press-drag on empty deck moves it; opacity fades via `ui.set_opacity` on the area ui (Frame + children inherit painter opacity); proximity check uses the deck rect stored in DeckState from the previous frame.
- Phase 8b gotchas: kittest 0.36's default step_dt is 0.25 s and egui's double-click window is 0.3 s, so a double-click test must queue both press+release pairs into ONE pass (push 4 PointerButton events, then run); stepping between clicks lands 0.5 s apart and only counts as single clicks. `response.double_clicked()` is evaluated on the release frame (CLICKED flag + `pointer.button_double_clicked`), so checking it before the clicked/drag branch works. egui 0.36 `WidgetType` has no `ListItem` variant (use `SelectableLabel`); `Harness` default viewport is large enough for full-height widgets. Track-header hover uses `ui.rect_contains_pointer`, not `response.hovered()`: the visible toggles take the pointer and would otherwise hide themselves again.
- Phase 14b gotchas: an `Area` at `Order::Tooltip` CANNOT hold interactive widgets (egui makes widget responses empty there), so the tour's dim is a non-interactable Foreground area created before the interactable callout area; same-Order areas paint in area_order (creation order), and `ctx.layer_painter` layers are painted AFTER registered areas in that Order, so never use layer_painter for an underlay. The help window only reaches its `extra` callback for ids that ARE in the book, so an app must add a body-less topic whose id is `KEYBOARD_PAGE_ID` (the gallery adds one in help.rs); the constant alone does not create a page. `Context::run_ui` takes `FnMut`, so a test helper passing an `FnOnce` through it needs a `RefCell<Option<..>>` + `take()`. `KeyboardShortcut::format(&egui::ModifierNames::NAMES, false)` gives "Ctrl+Z" without a context (used by `validate`); `ctx.format_shortcut` also uses NAMES on Windows, so splitting on '+' yields the caps. `egui::ModifierNames`/`KeyboardShortcut` are re-exported at the root. `CornerRadius: From<f32>` exists, so token f32 radii go straight to `rect_filled`.
